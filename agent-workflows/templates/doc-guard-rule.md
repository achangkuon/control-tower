## Documentation Close Gate (global policy; hook enforcement is runtime-specific)

- A session that SHIPPED work — a commit that lands via PR, `gh pr merge`, `supabase db push`, or a migration — CANNOT be closed until the documentation is reconciled. Not optional, not "later".
- Fixed close sequence: (1) deliver through the repository's declared policy (direct push or PR/merge), (2) reconcile the required docs, (3) only then close the session.
- The docs to update: the active OpenSpec/docs planning record (the technical source of truth), `mem_session_summary`, and the project's Notion page via `chanks-5-session-doc` when enabled. An exact project opt-out of `notion.enabled: false` in `.session-doc.json` disables only the Notion projection; it never disables the OpenSpec/docs or Engram evidence.
- "I made the PR / did the db push" is NOT done. **Done = shipped AND documented.** If you shipped and did not touch the status docs, you are not finished.
- In Claude Code, enforced by a hook (`~/.claude/hooks/doc-guard.sh`) in doc-managed repos (those with `openspec/` or `.session-doc.json`): the Stop gate BLOCKS session close when a ship happened without a matching doc update. The hook has two modes and picks by evidence: in a repo migrated to the Zona model —one that has `openspec/plan.yaml`— **only editing that file clears the gate**, and `STATUS.md`, Notion and `mem_session_summary` do not; in a legacy repo the older backends still clear it. Edit with the Edit or Write tool, since the check runs on those two: a correct file written with `sed` or `python3` leaves the gate armed. When a delivery genuinely closed no planned work, the exit is a standalone line reading exactly «nada que registrar». Do not try to bypass it — update the docs.
- Other agents follow the same documentation policy without assuming that the Claude Code hook runs in their harness. Project instructions take precedence for documentation destinations, including an explicit no-Notion policy.
