# Issue-patch closure (V2, not Session closure)

For an issue patch routed through `../SKILL.md`'s Issue-Patch Mode, the responsible parent
collects the exact human approval (issue, base, outcome, worker, files, Cimientos, Recursos),
reproduced symptom, worker identity and terminal evidence, checks, review result, full
immutable commit, branch and serial integration evidence. Require fresh Git proof that the
reported candidate commit belongs to the exact issue branch/worker and is an ancestor of
integrated master; verify changed files against approved scope. Close the issue only against
named tests that demonstrate the original symptom is repaired at the integrated immutable
commit, not on a promise, report or outbound send. Missing evidence, conflict, identity drift
or failed checks leave the patch open and preserve the worker. A review result is evidence,
never delivery permission.

Check actual delivered paths against the repository `AGENTS.md` reinstall rules exactly as for
a Session; missing required human confirmation, installation or verification is pending closure.

When no planned work is closed, declare «nada que registrar»; never add a patch Session, write
`openspec/plan.yaml`, call `radar archivar`, require Radar `COMPLETO`, or increment plan
progress for a patch. Return issue closure evidence separately from Session `entrega.commit`
delta. Only then request patch retirement under `retiro.md`. This documentation does not prove
execution, installation, or live Herdr retirement.
