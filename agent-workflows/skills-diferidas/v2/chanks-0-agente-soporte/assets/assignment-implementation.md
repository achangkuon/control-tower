# Implementation handoff

Fill every placeholder and hand one bounded Session to the selected implementer.
This handoff authorizes no plan mutation, lock, dispatch, or delivery by itself.
How the work is implemented, tested, reviewed and delivered belongs to Gentle AI.

```text
IMPLEMENTATION HANDOFF: <SESSION_ID>

Project/repository: <IDENTITY>
Verified base: <BASE_REF>@<SHA>
Session discriminator: <native encargo | legacy>
Resume basis: <same Session identity plus native ODD record, code, and evidence | first pending Módulo for legacy>
Branch and checkout: <FULL_BRANCH_REF> / <ABSOLUTE_WORKTREE_OR_PRIMARY_CHECKOUT>
Exact authorized files: <PATHS_OR_READ_ONLY>
Encargo: <FOUR_PART_SUMMARY>
Dependencies and authority: <EVIDENCE>
Compatibility: <CIMIENTOS_RECURSO_EVIDENCE>
Forbidden scope: <PATHS_AND_EFFECTS>
Responsible parent: <IDENTITY_AND_RETURN_CHANNEL>
```

V1 has no admission step: the human-chosen Session reaches Gentle AI through `chanks-4-puente`.
Verify repository, HEAD, branch, checkout, and compatibility before editing. A native Encargo keeps the same Session identity
and reconciles Gentle AI's technical record, code, and evidence; a legacy Session continues at first
pending Módulo for legacy. Do not choose another Session, widen scope, or create a fake lock.

When the work is done, report to the responsible parent the delivered commit, changed paths, and the
checks Gentle AI observed. The report authorizes no delivery; the parent verifies integration and
closure separately.
