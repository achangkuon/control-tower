## Activation Contract

Load after user ideas or points are clarified and approved, before granular planning. Make one
lightweight cosmetic classification for the same feature; this is not a parent router or a planning step.

## Hard Rules

- Suggest only relevant visible messages. This is not an evidence or technical evaluator: do not evaluate evidence, technical feasibility, or enforcement.
- Assign one responsible identity to each actual action: 💪 Chanks owns method, planning, admission, shared-file coordination, evidence consumption, and documentation closure. 🗼 Torre owns only actual Tower runtime operations; manual Main is not Tower. Gentle AI owns implementation, testing, and review under its native identity.
- Tower is off here. Do not relabel method actions as Tower actions or duplicate Gentle AI ownership.
- Distinguish permission from effect completion, and notice from proven enforcement. A skill's presence is not runtime-proven.
- No separate Session by default. Never add a planning level, status, queue, registry of work, gate, alternate plan, plan.yaml, or ROADMAP update. No-message or uncertain cosmetic preference never blocks admission or planning.
- Do not introduce scope expansion; security controls are outside this aesthetic check. Carry an in-scope copy proposal through ordinary scope approval without another human gate.

## Decision Gates

| Classification | Return |
| --- | --- |
| A message would clarify a relevant feature moment | One small suggestion. |
| No useful message is apparent | `No messages needed`. |
| A requested message implies new scope or a security control | Mark it outside this aesthetic check; do not invent it. |

## Execution Steps

1. Identify the feature's visible user or operator moment and classify whether a message helps.
2. Name the responsible identity only for the actual message-related action.
3. Return the suggestion to the responsible parent for the same feature's implementation Session, or the no-message result.

## Output Contract

Return either `No messages needed` or: feature; responsible identity; actual event/moment;
proposed message addition/update; and rationale. Write human-facing output in the conversation
language. This is a static cosmetic suggestion, not live message execution or runtime/UI enforcement.
