## Decisions and implementation

- Public `SKILLS`, `OWN_SKILLS`, `CHANKS_SKILLS`, source inventory and legacy marker/rendering helpers remain compatible for Hermes and snapshot consumers. Hermes is outside the four-runtime Tower migration.
- Only actual runtime writes use the separate personal roster: `chanks-0-agente-soporte`. The 23 previously managed V1 skills are handed to Tower without removing files or links. Product-only `control-tower` is not falsely reported as previously managed.
- The parent's initial request to install deferred non-V1 skills was corrected. All five deferred skills retain their original non-installation and reversible retirement behavior.
- Normal installs preserve legacy blocks and print a one-line migration hint. They update only the new personal blocks; Codex's absent-block policy avoids legacy/new alias duplication. No legacy session-routing/plan-naming or signature deployment is performed by the normal runtime writer.
- Three templates use `chanks:*` markers and the consistent `Generated by Chanks (personal configuration) — not part of Control Tower` provenance header.
- `--migrate-to-tower` is read-only unless `--apply` is explicit. It preflights every file, backs up all affected files before the first edit, replaces the three legacy personal blocks, removes superseded routing/plan-naming, preserves protected/unmarked bytes, refuses ambiguous markers and symlinks, and makes no second-run changes.
- Existing assertions were updated only for intentionally changed runtime writes. The final two additional assertions now require legacy routing preservation and absence of personal writes to Tower's `chanks-1-prd` destination.
