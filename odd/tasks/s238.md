# S238 — Copiloto: foco por conversación, panorama y tarjeta de etapa

Subordinate execution continuity only, not a product plan.

## Objective

A deterministic tool `copiloto` that remembers the focus of each conversation
and turns Radar into the small stage card the agent and the human read:

1. `copiloto foco <ninguno|idea|S###>` records the conversation's focus.
   Focus is per conversation; a new conversation starts at `ninguno`.
2. The work copy of a Session that carries a dispatch marker fixes the focus
   as a fact, without asking.
3. `copiloto tarjeta` prints, deterministically and from Radar only:
   - focus `ninguno` → one panorama line at the start, then nothing (Etapa 0);
   - focus `idea` → the Etapa 1 card (close ambiguities + skill);
   - focus `S###` → the stage of `radar etapa <S###>`, its skill, next step
     and authorized files; Etapa 3 with the pilot switch on asks the blocking
     «¿con piloto automático o en esta conversación?».
   - Cards are 1 to 3 lines signed 🧭.
4. `chanks-etapa.sh` calls `copiloto`, retiring `CHANKS_PREVIOUS_ETAPA_JSON`.
5. `install-copiloto.sh` follows the `install-piloto.sh` pattern.

## Constraints

- Guidance, never a lock. No new gates, no writes outside the Git common dir.
- The focus is never fixed without human approval, except the work-copy fact.
- Engram is not a source: only Radar decides stage and panorama.
- In Etapa 4 the card never repeats or contradicts Gentle AI.
- Strict TDD with RED observed per stage.

## Technical interpretation

- State lives in the Git common dir under `chanks/copiloto/`, next to the
  pilot's state, so it survives every linked worktree. The tool is the only
  writer; Radar never reads it.
- The conversation is named by, in order: `--conversacion`, the
  `COPILOTO_CONVERSACION` env, the `activa` pointer file, else `principal`.
  Distinct names never share a focus; an absent focus file is `ninguno`.
- Radar is read through `radar etapa`, `radar sesion` and `radar status --json`
  resolved exactly like the pre-push gate (PATH, `RADAR_BIN`, fixed install),
  never a binary inside the checkout, through one replaceable read seam.
- `copiloto tarjeta` derives the stage, never invents it. A Radar refusal is
  shown as guidance naming the reason.
- The work-copy fact is read from `<common>/chanks/despachos/*.json`: a
  `radar.despacho/v1` marker whose absolute `worktree` equals the current
  checkout.
